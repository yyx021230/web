# 内容生产、人工审核与云手机发布闭环（明确版）

更新日期：2026-08-07

> 本文是该功能的唯一产品口径。旧的 Agent、发布助手和自动发布文档只作为历史参考；后续数据模型、页面、接口和排期均以本文为准。

## 一句话定义

系统通过已配置并发布的工作流，把一批内容需求拆成多条待发布笔记；每条笔记经过机器预审和人工审核，只有审核通过且未被修改的版本，才会在排期时间由平台调用云手机接口自动发布，随后回查真实帖子并进入数据复盘。

## 与现有 AI 生图、工作流的关系

这三个功能相互连接，但不能合并成一个功能：

| 功能 | 定位 | 是否保留独立入口 | 与新闭环的关系 |
|---|---|---|---|
| AI 生图 | 用户临时创作、图生图、单独生成和下载图片的工具 | 是，原 AI 生图页面和任务继续保留 | 工作流可以在内部调用生图能力；用户也可以把独立生图结果手工选入内容项 |
| 工作流 | 批量内容生产的执行引擎 | 是，继续配置、发布、授权和查看运行日志 | 新的内容生产批次必须选择一个已发布的工作流版本来执行 |
| 内容审核与发布 | 管理生产结果、版本、审核、排期、云手机发布和复盘的业务系统 | 新增独立入口 | 接收工作流标准输出，不直接实现文案模型或生图模型 |

明确规则：

1. 新功能不删除、不改名、不覆盖现有 AI 生图。
2. AI 生图产生的普通任务仍只属于 AI 生图，不会自动进入审核发布。
3. 内容批次由工作流生产；工作流内部可以调用文案模型、AI 生图、OCR、知识库和其他步骤。
4. 只有用户明确创建“内容生产批次”，工作流结果才会转换为待审核内容项。
5. 审核模块只依赖统一输出格式，不依赖工作流内部用了哪个模型；以后更换工作流不会影响审核和发布数据结构。
6. 批次必须记录使用的工作流 ID 和发布版本，后续修改工作流只影响新批次，不影响已经生成和审核的历史内容。

## 一、先明确九个结论

1. **一个生产批次可以包含很多条内容。** 例如一次生产 57 条内容属于一个批次，但 57 条内容必须分别保存、分别审核、分别发布。
2. **一条内容不等于一次 AI 生图任务。** 新内容由工作流组织生产，工作流内部可以产生多个文案、生图或 OCR 子任务；真正贯穿审核和发布的是“内容项”。
3. **事实来源与参考文案必须分开。** 政策、价格、权益等以指定事实来源为准；文案库只学习表达结构和风格，不能反向修改事实。
4. **机器预审不能代替人工审核。** 第一版所有准备发布的内容都必须经过人工审核，不按风险分数自动放行。
5. **审核针对具体版本。** 审核通过后，标题、正文、标签、图片顺序、车型或目标账号发生变化，原审核立即失效，必须重新审核。
6. **平台负责业务决策和排期。** 云手机不决定发什么、何时发、发到哪个账号，只执行平台已经审核通过并到期的发布任务。
7. **云手机只接收标准发布任务。** 平台不能向云手机下发任意脚本或任意 ADB 命令，手机端的 UI 适配由云手机服务自身维护。
8. **接口受理不等于发布成功。** 只有回查到真实帖子，且账号、时间和内容匹配后，平台才标记为“已发布”。
9. **不确定是否发成功时不能直接重试。** 必须先查询云手机状态并回查账号主页，避免同一内容重复发布。

## 二、当前系统真实情况

| 当前能力 | 已有内容 | 能否直接复用 |
|---|---|---|
| AI 生图 | `ai_tasks` 保存模型任务和图片结果 | 完整保留为独立工具，也可以作为工作流内部能力或内容素材来源 |
| Dify 工作流 | `dify_tasks` 保存工作流输入输出 | 作为新内容生产功能的主要执行引擎，需要补标准输出和版本锁定 |
| 文案库 | `copywritings` 保存正式文案 | 作为参考文案库使用，不承担发布审核 |
| 抓取审核 | `scrape_tasks`、`scrape_candidates` 审核采集来的文案是否入库 | 不能复用为发布审批，这是另一种业务审核 |
| 发布管理 | `/publish` 可以手工填写并通过云登浏览器发布 | 可以保留为旧发布方式，但目前没有审核门禁 |
| 发布事实 | `xhs_posts` 保存发布中、定时、成功、失败和帖子数据 | 继续作为发布结果事实表，不能承担全部生产与审核状态 |
| 手机云控 | 当前方案主要支持短信和二维码扫码 | 需要新增“小红书图文发布”能力和正式接口 |

因此，这个功能不是在现有发布接口前面简单加一个“审核按钮”，也不是重做 AI 生图，而是以工作流为生产引擎新增一层内容业务主线，再把工作流结果、素材和帖子结果接到这条主线上。

## 三、完整业务流程

```text
1. 创建生产批次
   选择已发布的工作流版本，填写活动目标、内容数量、事实来源、车型范围、可用账号范围和截止时间

2. 拆分内容项
   一个内容项代表未来的一条小红书笔记，提交审核前必须确定具体目标账号

3. 锁定来源
   保存事实来源快照和参考文案快照，区分“事实”与“表达参考”

4. 生产内容
   工作流批量运行，内部按配置调用文案、AI 生图、OCR 或知识库，输出标准图文结果

5. 生成内容版本
   每次提交预审都生成不可修改的新版本

6. 机器预审
   检查事实、敏感词、图片文字、车型一致性、图片比例、素材完整性等

7. 人工审核
   审核人查看最终图文预览、来源、机器问题和版本差异

8. 审核处理
   通过：锁定版本
   退回修改：填写具体意见，创建新版本后重新预审和审核
   作废：该内容不再进入发布

9. 创建发布单
   沿用审核版本中的目标账号并选择发布时间；更换账号必须创建新版本并重新审核

10. 到期前再校验
    检查审核仍有效、政策未过期、账号与云手机绑定正常、设备在线、素材可下载；政策过期则退回重新确认

11. 调用云手机接口
    平台下发标准发布任务，云手机在小红书官方 App 中执行

12. 回传与核验
    云手机回传步骤、截图和结果；平台再回查账号主页确认真实帖子

13. 数据回收
    将帖子 ID、链接和后续互动数据关联回原内容项，进入效果复盘
```

## 四、三个业务对象，不能混成一个

### 1. 生产批次

代表一次业务需求，例如“8 月购车政策生产 57 条内容”。

批次保存：

- 业务目标和截止时间。
- 需要生产的内容数量。
- 选用的工作流 ID、工作流发布版本和本次输入参数。
- 指定事实来源及其快照。
- 允许参考的文案、模板和素材。
- 车型范围、账号范围和负责人。
- 批次总体进度：共多少条、待生产多少条、待审核多少条、已发布多少条。

### 2. 内容项与内容版本

一个内容项代表未来的一条笔记；一个内容项可以经历多个版本。

每个版本必须完整保存：

- 标题、正文、标签。
- 图片列表、固定顺序、不可覆盖的对象版本和文件校验值。
- 车型、活动、政策日期和目标账号。
- 事实来源快照和参考文案快照。
- 使用过的 AI/工作流任务 ID、模型、提示词和参数。
- 机器预审结果。
- 创建人、创建时间和版本号。

审核通过的版本只读。任何内容修改都要复制为新版本，并重新审核。目标账号也是审核内容的一部分，发布单只能沿用审核时的目标账号。

### 3. 发布单与发布尝试

发布单代表“把某个审核版本发布到某个账号的一次业务决定”；发布尝试代表系统实际调用云手机的每一次执行。

这样拆分后：

- 修改排期不需要改内容版本。
- 一次网络重试不会生成第二条业务发布单。
- 云手机失败后可以保留完整的多次尝试记录。
- `xhs_posts` 只保存最终帖子事实，并关联发布单和审核版本。

第一版默认一条内容项只发布到一个账号。确需多账号发布时，应复制成新的内容项分别审核，避免同文多发和责任不清。

## 五、状态不能只用一套

### 内容项状态

```text
草稿
  -> 生产中
  -> 待预审
  -> 预审不通过 / 待人工审核
  -> 退回修改 / 审核通过 / 已作废
```

规则：

- 预审不通过只能返工，不能进入发布。
- 退回修改后必须创建新版本。
- 审核通过后修改内容，状态回到待预审。

### 发布单状态

```text
待排期
  -> 已排期
  -> 发布前检查
  -> 等待设备
  -> 发布中
  -> 待核验
  -> 已发布 / 发布失败 / 需人工处理 / 已取消
```

规则：

- “接口已受理”和“手机已点击发布”都不能直接记为已发布。
- 验证码、登录失效、风控提示和 UI 无法识别统一进入“需人工处理”。
- 状态不确定时进入“待核验”，不得自动再发一次。

## 六、机器预审到底检查什么

| 检查组 | 具体检查 | 处理方式 |
|---|---|---|
| 事实与政策 | 车型、价格、优惠、时间、区域、政策条件是否与事实来源一致 | 不一致直接阻断 |
| 文案风险 | 敏感词、变体、谐音、站外引流、绝对化承诺 | 高风险阻断，疑似项提示人工 |
| 图片文字 | OCR 读取图片中的车型、价格、权益、敏感词 | 与正文或事实来源冲突直接阻断 |
| 图文一致 | 文案车型与图片车型一致，权益和日期一致 | 不一致直接阻断 |
| 素材质量 | 图片存在、顺序完整、尺寸比例、清晰度、重复图、版权信息 | 硬错误阻断，质量问题提示 |
| 平台格式 | 标题、正文、标签和图片数量符合当前规则 | 不符合直接阻断 |
| 账号适配 | 内容品牌、部门、账号定位和目标账号是否匹配 | 不匹配交人工确认或阻断 |

机器预审必须输出结构化问题：问题类型、严重程度、位置、原值、依据、建议修改方式。不能只返回一个总分。

## 七、人工审核页面必须看到什么

审核人不能只看到一段文案，页面至少同时展示：

- 最终手机比例的图文预览和所有图片。
- 标题、正文、标签和图片 OCR 文字。
- 目标小红书账号、计划时间和负责人。
- 事实来源与当前内容的逐项对照。
- 参考文案来源，明确标注“仅供表达参考”。
- 机器预审问题及处理结果。
- 当前版本与上一版本的差异。
- 通过、退回修改、作废三个动作。

退回修改必须填写意见，并能具体标记“文案第几段”或“第几张图片”。批量审核可以提高效率，但系统仍要为每一条内容保存独立审核结果。

默认实行提交人与审核人分离。管理员紧急代审必须填写原因并进入审计日志。

## 八、云手机和本平台各负责什么

| 本平台负责 | 云手机服务负责 |
|---|---|
| 内容生产、来源管理和版本管理 | 设备、App 实例和登录状态管理 |
| 机器预审和人工审批 | 把小红书账号映射到具体设备和 App 槽位 |
| 发布账号选择和排期 | 下载并校验发布素材 |
| 到期时创建发布任务 | 唤醒设备并打开小红书官方 App |
| 账号权限、并发和发布频率 | 填写标题正文、上传图片、执行发布 |
| 展示进度、失败处理和人工接管 | 识别挑战页面并停止错误操作 |
| 回查真实帖子和同步数据 | 回传步骤、截图、结果和错误原因 |

重要边界：本平台下发的是“发布内容包”，不是一段会随时变化的 UI 脚本。小红书 App 页面改变后，由云手机团队更新执行器，本平台接口保持稳定。

## 九、云手机接口的明确约定

### 1. 账号绑定

云手机平台维护：

```text
小红书稳定账号 ID
  -> 云手机设备 ID
  -> App 实例/分身槽位
  -> 当前登录状态
```

内容平台只传小红书稳定账号 ID，不在业务代码中写死手机型号、坐标或 App 分身名称。更换手机时只更新云手机侧绑定。

### 2. 创建发布任务

```http
POST /openapi/v1/xhs/publish-jobs
```

最小请求字段：

```json
{
  "publishJobId": "平台发布单ID",
  "idempotencyKey": "同一发布单固定不变的幂等键",
  "xhsAccountId": "小红书稳定账号ID",
  "contentVersionId": "已审核内容版本ID",
  "title": "标题",
  "content": "正文",
  "tags": ["标签1", "标签2"],
  "images": [
    {
      "url": "短期签名下载地址",
      "sha256": "文件校验值",
      "mimeType": "image/png",
      "width": 768,
      "height": 1024
    }
  ],
  "callbackUrl": "平台回调地址"
}
```

第一版由内容平台负责定时。只有到达发布时间，平台才调用云手机创建立即执行任务，避免两边各维护一套定时器。

### 3. 查询与取消

```http
GET  /openapi/v1/xhs/publish-jobs/{remoteJobId}
POST /openapi/v1/xhs/publish-jobs/{remoteJobId}/cancel
```

### 4. 状态回调

云手机回调至少包含：

- 平台发布单 ID、云手机任务 ID 和事件 ID。
- 当前状态和执行步骤。
- 设备 ID、App 实例和发生时间。
- 截图地址。
- 成功时的帖子 ID、帖子链接；拿不到时明确为空。
- 失败时的标准错误码、是否可重试和错误说明。

建议状态：

```text
accepted
preparing
uploading
publishing
published_candidate
manual_required
failed
cancelled
```

`published_candidate` 只表示手机侧认为已发布，内容平台完成主页回查后才转为最终“已发布”。

### 5. 接口安全与可靠性

- 使用独立 API Key，并通过时间戳和 HMAC 签名请求与回调。
- `publishJobId + idempotencyKey` 在云手机侧必须唯一，重复请求返回原任务，不能再发一次。
- 图片使用短期签名 URL，云手机下载后校验 SHA256。
- 平台收到回调后按事件 ID 幂等入库。
- 回调丢失时平台主动查询任务状态。
- 同一小红书账号同一时间只能执行一条发布任务。
- 云手机不能执行平台下发的任意 shell、坐标脚本或无白名单命令。

## 十、成功、失败和重试怎么判断

| 场景 | 系统处理 |
|---|---|
| 云手机离线 | 发布单进入等待设备，超过允许时间后转人工，不丢任务 |
| 账号未登录 | 进入需人工处理，创建扫码/验证码任务，不自动反复登录 |
| 图片下载失败 | 可自动重试下载，不重复创建发布任务 |
| App 页面变化 | 停止执行并回传截图和当前步骤，由云手机侧更新适配 |
| 明确网络失败且尚未点击发布 | 最多按策略重试同一个远端任务 |
| 点击发布后接口超时 | 进入待核验，先查云手机和账号主页，禁止直接重发 |
| 返回成功但没有帖子 ID | 在时间窗口内按账号、标题、正文前缀和图片特征回查 |
| 回查找到匹配帖子 | 写入 `xhs_posts`，保存帖子 ID、链接和发布时间 |
| 回查没有找到 | 保持待核验或转人工，不能假装成功 |
| 重复回调 | 按事件 ID 幂等忽略，不重复推进状态 |
| 帖子之后被删除 | 后续同步更新为已删除，保留原发布证据 |

## 十一、页面只需要四个工作区

### 1. 内容生产

- 批次列表和批次进度。
- 内容项列表。
- 选择已发布工作流版本并填写批量输入。
- 事实来源、参考文案、车型和目标账号配置。
- 查看工作流运行、标准输出、人工编辑和版本历史。

### 2. 审核中心

- 待审核队列。
- 完整图文预览、来源对照、机器问题和版本差异。
- 通过、退回修改、作废。

### 3. 发布中心

- 已审核待排期、今日待发布、发布中、需人工处理和失败任务。
- 账号、设备、登录状态和排期冲突。
- 取消、改期、人工接管和安全重试。

### 4. 内容复盘

- 已发布帖子及其原内容版本。
- 浏览、互动、投流和线索数据。
- 按车型、主题、模板、提示词和账号分析效果。

现有 `/publish` 页面保留为“手工发布/旧链路”，第一版不要直接改造成审核中心，避免旧业务和新闭环互相影响。

## 十二、最小数据改造

建议新增：

| 表 | 作用 |
|---|---|
| `content_batches` | 一次批量生产需求 |
| `content_items` | 每一条未来笔记的主记录 |
| `content_versions` | 不可修改的完整图文版本与来源快照 |
| `content_qa_reports` | 每个版本的机器预审结果 |
| `content_reviews` | 审核人、决定、意见和审核版本 |
| `publish_jobs` | 审核版本、目标账号、排期和最终状态 |
| `publish_attempts` | 每次云手机调用、远端任务 ID 和结果 |
| `publish_events` | 云手机回传的步骤事件和截图 |
| `cloud_phone_account_bindings` | 小红书账号与云手机账号绑定标识 |

现有表的关系：

- `content_batches` 固定关联本次使用的工作流及其发布版本。
- `dify_tasks` 作为批次和内容项的生产运行记录；工作流内部产生的 `ai_tasks` 继续作为子任务血缘。
- 独立 AI 生图任务只有被用户明确选入内容项时，才记录为该内容版本的素材来源。
- `copywritings` 作为参考来源关联到内容版本，不迁成审核记录。
- `xhs_posts` 增加 `publish_job_id` 和 `content_version_id`，继续保存最终发布事实和互动数据。
- `scrape_*` 审核表保持不变，不与发布审批混用。

## 十三、权限和审计

| 角色 | 权限 |
|---|---|
| 内容运营 | 创建批次、生产和修改内容、提交审核、查看自己负责账号 |
| 审核人/负责人 | 查看部门待审内容、通过、退回、作废、调整排期 |
| 发布管理员 | 管理账号与云手机绑定、处理异常、受控重试和取消任务 |
| 企业管理员 | 配置规则、角色、账号范围、全局审计和紧急代审 |

必须审计：

- 谁创建和修改了哪个版本。
- 使用了哪些事实来源、参考文案、模型和素材。
- 机器检查发现了什么。
- 谁在什么时间审核了哪一版，给了什么意见。
- 谁设置或修改了账号和排期。
- 平台向云手机下发了什么，云手机每一步返回了什么。
- 最终发布到哪个账号、帖子 ID 和链接是什么。

## 十四、第一版明确做什么

第一版只跑通一个受控闭环：

- 只支持小红书图文笔记。
- 支持一个生产批次下多条内容项。
- 通过已发布工作流版本生产内容，不覆盖独立 AI 生图功能。
- 事实来源和参考文案分开保存。
- 文案和图片形成不可修改版本。
- 机器预审后必须人工审核。
- 审核通过后支持立即发布和平台排期。
- 只接一个云手机发布供应方。
- 使用测试账号真实发布。
- 记录完整步骤、截图、错误和帖子链接。
- 发布后回查并同步基础互动数据。

第一版不做：

- AI 自动审批。
- 未经人工审核直接发布。
- 多平台同时发布。
- 平台远程下发任意手机脚本。
- 自动绕过验证码、二维码或风控挑战。
- 状态不确定时盲目重新发布。
- 一开始就做大规模多租户批量自动发布。

## 十五、建议开发顺序

### 阶段 1：只做生产与审核，不连接真实云手机

- 建立批次、内容项、版本、预审和审核数据模型。
- 定义工作流标准输出，并把工作流运行结果转换为内容项。
- 建立内容生产页和审核中心。
- 使用 Mock 发布器验证审核门禁和状态流转。

验收：一批 10 条内容可以分别生成、预审、审核、退回和重新提交，未审核版本绝对无法创建发布单。

### 阶段 2：定义并联调云手机接口

- 云手机侧实现账号绑定、创建任务、查询、取消和回调。
- 本平台实现签名、幂等、素材签名地址和事件接收。
- 只用一个测试账号人工触发真实发布。

验收：同一个请求重复发送不会产生两条帖子；每一步有状态和截图。

### 阶段 3：加入排期和异常恢复

- 平台定时调度到期发布单。
- 增加设备离线、登录失效、待核验、人工接管和安全重试。
- 同账号串行和发布频率限制。

验收：服务或云手机短暂断线后任务不丢，不重复发布。

### 阶段 4：发布后数据闭环

- 回查帖子并关联 `xhs_posts`。
- 同步互动和投流数据。
- 按来源、车型、模板和账号做内容效果复盘。

验收：任意看板数据可以反查到原内容版本、审核记录和发布证据。

## 十六、最终验收场景

用一个包含 10 条内容的真实批次验收：

1. 10 条内容分别绑定事实来源、参考文案、车型和目标账号。
2. 机器预审故意拦截 2 条事实错误和 1 张图片敏感词。
3. 其余内容进入人工审核，其中 1 条被退回修改。
4. 返工后产生新版本，旧版本不可再发布。
5. 审核通过的内容中，2 条立即发布，5 条按不同时间排期。
6. 重复调用其中一个云手机任务，验证只产生一条帖子。
7. 模拟手机离线、登录失效、接口超时和回调重复。
8. 所有成功内容回查到真实帖子 ID 和链接。
9. 所有失败内容能看到失败步骤、截图、错误原因和处理建议。
10. 发布后的互动数据能关联回内容项、审核版本和生产批次。

全部通过后，才算“内容生产 → 人工审核 → 云手机自动发布”真正完成。
