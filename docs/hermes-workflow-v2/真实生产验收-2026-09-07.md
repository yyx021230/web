## 已定位、尚未修改的问题

### 1. 单个字体关键词不能决定图片版式

共享分类规则把“手写”作为手账正向条件。#54 原始提示词是“暖棕调极简斜切建筑空间”，只把标题字体指定为“毛笔手写”，因此被错误放进 note_poster。改造提示词忠实保留建筑构图，成图也成为建筑光影海报，并非生成接口偏离已经正确选好的手账。

拟修方向：手账需要手账、便签、纸张、贴纸等布局/材质依据；毛笔或手写字体只能作字体特征，不能独自决定手账类型。先修选材分类，再测，不让生图强行把错误母版大改成手账。

### 2. 配置名与金额误拦导致额外轮次

读取保存的四次 `xhs_validate_copy` 调用参数，用同一政策和原校验函数离线重放，结果：

1. “政策未提供的金额：6.39w”；“优先看510悦享版、想要更完整体验建议对比悦享版、重点看405舒享版”被整体当成配置名。
2. 改用 405悦享版后，前缀“想要更完整体验建议对比”仍被一起捕获，因此仍报错。
3. 泛称“可以从入门版”也被当成具体配置名报错。
4. Agent 绕开这些表达后通过。

`CONFIG_RE` 在“XX版”前贪婪包含最多 16 个非标点字符，且将“入门版”等泛称当具体登记配置。金额校验使用原字面串包含判断，未用已存在的数值归一化能力，因此 6.39w 与已提供的 ¥63,900 没被认作等值。

拟修方向：只核对真正的配置实体；金额按单位归一后比对并保留语义/条件约束。不放宽对真实未提供价格、具体配置、补贴条件的校验。禁止以“关掉所有校验”解决误判。

### 3. 程序通过不等于内容全部有依据

- 第一篇把母文泛称的“补贴、礼品”具体化为“补贴、外饰、选装基金、充电桩服务包”。这些名词来自当前政策，但仍比母文具体；按“不硬加”的要求需要进一步收敛。
- 第二篇的后排舒展、风噪、悬架体验等描述，在本轮 A05 政策资料中没有相应依据；不能因为母文是另一车型的试驾，就默认可迁移成 A05 的真实试驾结论。未据此假称完成产品体验真实性核验。
- 两篇全文、emoji、末尾话题和母文对照都已保留。既有硬校验主要检查金额、配置、旧车残留等，无法保证全部自然语言体验事实有依据。

### 4. 其他验证边界

- 读取的近期帖子共 3158 条，但账号 42 匹配到 0 条。已确认线上账号身份一致，因此本轮不能证明账号历史去重有效，也不能据此断言串号。
- 本地 SQLite 的 created_at 默认记录 UTC（03:13），started_at/finished_at 使用北京时间（11:14）；当前界面把无时区字符串统一作北京时间解析，导致创建时间少显示 8 小时。未擅自迁移或重写历史时间。
- 开发页仍观察到间歇性 Network Error 提示，重试后卡片和原图可展示；未宣称开发环境网络绝对稳定。
- 仅测试两篇、一个账号；不能外推到 8 账号 40 篇持续稳定性。也没有测试本轮未选的全部类型。
