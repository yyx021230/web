### 实际代码链路

1. Web 选择账号，将 `environment_id` 持久化在任务账号参数中；Worker `web_worker.py:build_run_config` 使用此 ID 构建生产账号，不用展示名称做模糊匹配。
2. `run_daily_8x5.py:OnlineData.recent_posts` 按所选 ID 请求 `GET /api/backend/xhs/account-notes?page=1&limit=15&environment_id=ID&status=active`。逐账号读取、无日期窗口；拒绝混入其他账号/不完整响应，接口失败不伪装成空历史。
3. 账号接口按 `published_at DESC NULLS LAST` 排序。Runner 再核对账号、状态、排序与重复 ID，保存 `account_history.snapshot.json`。
4. `prepare_portfolio` 把各账号历史传给 `select_diverse_rows`。先随机候选，避开与账号历史/同批母文高度重叠的结构。候选不足时只扩展一次，再不足会有记录地放宽，不无限循环。
5. `build_avoidance_briefs` 保存最近 15 条标题和可用正文；`copy_job` 把对应账号的 brief 传入每篇独立 Worker。
6. `copy_worker` 将这 15 条完整 JSON 嵌入发给 Hermes 的提示词，并要求只避高度雷同，不因同车型、同政策、同话题或普通相似硬改母文。保存的 `.input.json`、输出工具轨迹证明真实走了此入口；并非仅有页面提示。无法据此量化模型对每条历史的“注意程度”。
7. `account_repetition_check` 对生成稿和历史全文做归一化 4-gram Jaccard 检查，阈值 0.85。不是语义相似度百分比。高度相似添加 warning，`blocking=false`，不因此自动无限重生。
8. 结果随 delivery → API ingest → `hermes_workflow_posts.source_detail.account_history/account_repetition`，在“文案对照”展示。

### 能力边界

- 对近乎照搬的大段结构有实际避让和检查；对换词后的语义雷同不是可靠保证。
- 缺正文/短正文降低覆盖面；短标题不足以认定整篇重复。
- 图片没有与最近 15 篇已发图片做视觉相似度比对。图片模板的历史避让使用生成交付台账，不能称为账号近期成图视觉去重。
- 相似度报告针对原始生成稿；人工编辑后不会自动重算。
- 本次不擅自提高阈值严格度、不触发账号抓取、生成或重生任务。
