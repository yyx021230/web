已在用户的 Windows 服务器上构建并离线验证 Hermes Linux Docker Worker。

线上 frontend/backend 仍是 0.3.18，进程启动时间未变，站点 HTTP 200。
发布计划保持“开发中”，不保存、不调用发布接口。

## 实现范围

- 去掉生产 Worker 对 zsh 启动和 `/Users/...` 默认路径的依赖；Hermes repo/Python
  可配置，容器使用固定路径，Mac 默认仍使用 Apple Vision。
- Linux OCR 使用 RapidOCR 3.9.2 / ONNX Runtime 1.29.0，三个内置 ONNX 模型
  校验 SHA-256；断网可加载并识别，不需要临时下载模型或远程 OCR。
- 原始 OCR 文字和置信度保留；仅配置名比对兼容白名单内的繁简同字，保存转换审计。
  文案、母版随机策略、近 15 篇避重、金额/日期/车型/禁用词检查不变。
- 配置、政策同步状态、断点输出、Hermes home 分卷保存；新镜像更新发布所有的
  插件代码及技能文件，不覆盖用户更新的政策或历史状态。
- 启动时离线检查 Hermes 和三个私有复刻工具，再允许进入原有 Web 认领循环。
- 健康状态基于成功的 API 请求；SIGTERM/SIGINT 后不再认领新任务，等待当前任务结束。
- 默认 2 个文案/规划并发、5 个图片接口并发；容器限制 2 CPU / 1536 MiB。
  该值是当前服务器资源预算，不改变用户的账号篇数输入。
