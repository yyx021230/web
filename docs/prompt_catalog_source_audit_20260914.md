## 4. 建议的新库配额

第一阶段先做 80 条本地审核样本，每类 20 条；视觉和分类通过后再扩成 1000 条。

正式库建议保持四类均衡：

| 一级分类 | 数量 | 重点 |
| --- | ---: | --- |
| 产品视觉 | 250 | 电商主图、卖点、场景、材质和组图 |
| AI 短剧 / AI 漫剧 | 250 | 角色、场景、分镜、连续性和封面 |
| 海报营销 | 250 | 小红书、电商、活动、新品和品牌 KV |
| 汽车视觉 | 250 | 车型摄影、价格政策、功能卖点和线索海报 |

## 5. 每条素材的落库标准

- 标题、提示词、分类和标签必须是自然中文，不把英文原文塞进“中文提示词”字段。
- 每条提示词必须有明确用途，不能只有“高级、电影感、8K”等空泛形容词。
- 默认展示图使用 3:4；短剧分镜可额外记录 9:16，横版故事板可记录 16:9。
- 配图由我们自己的生图链路生成并保存到本地 / 对象存储，不热链第三方图片。
- 产品和汽车图优先走图生图，锁定商品、包装或车型外观，避免模型凭空改形。
- 海报中文字只保留必要标题和短卖点，价格、日期、二维码等业务字段优先后期叠加。
- 短剧类必须记录角色锚点、场景锚点、镜头、光线、动作和连续性约束。
- 去除真实品牌、未经授权 IP、真人肖像和虚构功效 / 价格 / 参数。
- 保存来源站点和参考链接，但成品提示词必须经过重写，不能整段复制第三方受保护内容。
- 入库前做文本相似度和图片感知哈希去重，避免“换个产品名但画面完全一样”。

## 6. 推荐执行顺序

1. 保留现有内部用户分享内容，不动用户自己的提示词。
2. 先建立四个一级分类及上述子类标签。
3. 从明确开放的模板源和中文案例中挑 80 个不同视觉方向，只提炼结构，不复制受保护原文。
4. 将 80 条重写成中文业务模板，用本项目生图服务生成自有 3:4 预览图。
5. 人工审核图片完整度、中文文字、产品 / 车型一致性和重复度。
6. 审核通过后再扩充到 1000 条，并只替换当前 `source_kind=external` 的旧目录。
7. 发布时保留来源、授权、生成模型、尺寸和审核记录，支持后续下架和追溯。
