# v0.2.0 发布与恢复手册

更新日期：2026-08-07

## 1. 版本目标

v0.2.0 建立可追溯、可验证、可备份、可回滚的发布基线，不修改现有业务统计口径。本版本上线前必须完成 Windows 环境演练；当前源码完成不等于已经上线。

## 2. 环境边界

| 环境 | 配置 | 数据库 | 用途 |
|---|---|---|---|
| 开发 | `.env.development` + `docker-compose.dev.yml` | 独立开发库 | 本地开发与联调 |
| 测试 | `APP_ENV=test` + `backend/.env.test.example` | 每个测试进程独立 SQLite | 自动化测试，禁止连接 Postgres 生产库 |
| 生产 | 根目录 `.env` + `backend/.env` | Windows 生产 Postgres | 正式业务 |

生产启动必须同时满足：

- `APP_ENV=production`
- `DEPLOYMENT_ENVIRONMENT=production`
- `PRODUCTION_CONFIRMATION=ALLOW_PRODUCTION_DEPLOYMENT`
- 非 SQLite 数据库和非默认数据库密码
- 已设置 `JWT_SECRET_KEY` 与 `XHS_WORKER_INTERNAL_TOKEN`

任一条件不满足，后端拒绝启动。

## 3. 发布前门禁

```bash
cd /Users/yyx/ztqc/web
python3 scripts/check_alembic_heads.py
python3 scripts/check_tracked_secrets.py
cd backend && .venv/bin/pytest -q
cd ../frontend && npm ci && npm run type-check && npm run build
cd .. && git diff --check
```

CI 必须全部通过。正式发布只允许干净工作区，并且当前提交必须存在与 `frontend/package.json` 版本一致的标签，例如 `v0.2.0`。

## 4. Windows 一次性准备

1. 将 `.env.production.example` 复制为 `C:\projects\web\.env`，填写真实密码，不提交 Git。
2. 保留并检查 `C:\projects\web\backend\.env` 中现有业务密钥。
3. 上传目录建议配置到 D 盘，例如 `UPLOADS_HOST_PATH=D:/ztqc-data/uploads`。
4. 备份目录默认为 `D:\ztqc-backups\web`，建议通过 `BACKUP_MIRROR_DIR` 再复制到另一块盘或远端。
5. Docker Desktop 必须已启动，C、D 盘空间满足备份和新镜像同时存在。

以管理员 PowerShell 安装每日备份和健康巡检：

```powershell
Set-Location C:\projects\web
.\scripts\windows\Install-DailyBackup.ps1
.\scripts\windows\Install-HealthMonitor.ps1
```

健康结果位于 `runtime\health\latest.json`，Docker 日志采用单文件 20 MB、最多 5 个文件的轮转策略。

## 5. 正式发布

```bash
cd /Users/yyx/ztqc/web
./deploy-to-windows.sh
```

默认使用 SSH Key。确需临时密码时只通过当前 Shell 注入 `WIN_PASS`，不得写入仓库。

发布脚本依次执行：

1. 编译 Linux AMD64 MCP。
2. 生成带版本号和 Git commit 的发布包。
3. Windows staging 解压并校验 Compose。
4. 构建不可变版本镜像。
5. 备份 Postgres 与上传文件并验证数据库备份。
6. 保存旧源码快照，停止应用服务。
7. 解压新版本，执行 `alembic upgrade head`。
8. 启动后端、AI Worker、前端并等待健康检查。
9. 写入 `.release/current.json` 和发布历史。
10. 任一步失败时恢复旧源码和发布前数据库备份。

## 6. 上线验证

```powershell
Invoke-RestMethod http://127.0.0.1:8000/version
Invoke-RestMethod http://127.0.0.1:8000/health/ready
Invoke-WebRequest -UseBasicParsing http://127.0.0.1:3000/
docker compose ps
```

必须确认版本、commit、环境均正确，并回归登录、生图、任务中心、主页同步、发布、运营看板、投流看板、图片访问和导出。

## 7. 手动备份与恢复

手动备份：

```powershell
.\scripts\windows\Backup-Release.ps1
```

恢复是破坏性操作，必须先暂停业务并确认恢复点：

```powershell
.\scripts\windows\Restore-Backup.ps1 `
  -BackupDir D:\ztqc-backups\web\20260807_020000 `
  -RestoreUploads `
  -StartServices `
  -ConfirmRestore
```

每月至少在隔离的演练环境执行一次恢复。目标为数据库/上传文件 RPO 不超过 24 小时，发布操作 RPO 为发布前一刻，应用恢复 RTO 不超过 30 分钟。

## 8. 版本回滚

```powershell
.\scripts\windows\Rollback-Release.ps1 `
  -PackagePath C:\projects\web\.release\packages\0.1.0-<commit>.tar.gz `
  -BackupDir D:\ztqc-backups\web\<release-backup> `
  -Version 0.1.0 `
  -Commit <commit> `
  -ConfirmRollback
```

回滚前记录故障时间、当前版本、目标版本和备份目录。不要使用 `git reset --hard` 或直接覆盖生产数据卷。
