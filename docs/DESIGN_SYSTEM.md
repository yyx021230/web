# 界面设计约定

本文件记录当前界面的实现依据，不是已下线编辑器的画布规范。新增页面应先复用现有组件和样式，再扩展 token。

## 设计来源

- 全局语义色、圆角和通用表面：`frontend/src/styles/globals.css`。
- 工作区侧栏、页面容器及响应式布局：`frontend/src/components/navigation/workspace-shell.module.css`。
- 生图页面的局部布局：`frontend/src/app/(main)/ai/studio.module.css`。
- 组件级样式可能使用 Tailwind 或 CSS Modules；不要让两套样式对同一尺寸相互覆盖。

## 颜色与表面

全局 token 保存为 HSL 分量，使用时写 `hsl(var(--primary))`，透明度写 `hsl(var(--primary) / 0.2)`，不要把它们当十六进制色值直接输出。

| Token | 浅色值 | 用途 |
|---|---|---|
| `--background` | `0 0% 100%` | 页面底色 |
| `--foreground` | `222.2 84% 4.9%` | 主文字 |
| `--surface` | `210 40% 98%` | 次级表面 |
| `--primary` | `239 84% 67%` | 主要操作 |
| `--primary-hover` | `240 73% 58%` | 主要操作悬停 |
| `--muted-foreground` | `215.4 16.3% 46.9%` | 次要文字 |
| `--border` | `214.3 31.8% 91.4%` | 分隔与边框 |
| `--ring` | `239 84% 67%` | 焦点状态 |
| `--workspace-bg` | `210 20% 96%` | 工作区背景 |

成功、警告、破坏性操作分别使用 `--success`、`--warning`、`--destructive`；已有 `.dark` token 覆盖。部分工作区表面仍有局部渐变和半透明白色，调整全局 token 不会自动改变这些局部效果。

## 工作区布局

外层 `.shell` 是 `100dvh` 的 flex 容器，侧栏默认宽 `256px`、收起为 `72px`，侧栏与内容区间距 `16px`。`.viewport` 使用 `16px` 外边距、`22px` 圆角和半透明白色表面；路由切换只更新右侧内容区，侧栏保持在位。背景是两层缓慢运动的网格渐变，不是单一纯色。

侧栏导航项高度 `32px`、字号 `13px`，选中状态由 `.navIndicator` 过渡呈现。不要为每个功能页再复制一套全局侧栏。内容区使用 `min-width: 0` 和自身滚动容器，避免窄屏时把整个页面撑出视口。`max-width: 767px` 和 `max-height: 800px` 有专门布局规则；新组件要在这两种条件下检查。

## 交互与可访问性

- 主操作和危险操作要有明确的文字或可访问名称；图标按钮不能只靠图形表达含义。
- 键盘焦点保持可见，优先使用 `--ring`；弹窗、菜单和表单按现有组件交互方式处理。
- 悬停、导航切换可以使用短促过渡；遵守现有 `prefers-reduced-motion` 分支，避免对减少动效用户强制播放背景动画。
- 异步请求展示真实的排队、进行中、失败和完成状态，不用一个永久转圈替代错误反馈；长列表注意稳定布局和图片占位，避免滚动时跳动。
- 生图、图库、数据看板的局部排版可以不同，但共享全局侧栏、色彩语义和焦点规则。
