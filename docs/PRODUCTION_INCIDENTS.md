# 生产故障记录

本文档记录已经确认根因的生产故障。每次修复必须同时记录现象、特征日志、根因、
永久修复和发布后验证，避免同类问题在后续部署中复发。

## 2026-08-20 验证码已输入但提交响应超时被误判为登录失败

### 现象

- 云登浏览器中已经输入验证码，部分账号页面也已经完成登录，但同步历史最终仍显示
  “等待小红书验证码超时”。
- `汽车圈摸鱼选手`、`底价猎人·新车管家` 的第一条短信订单均为 `received`，随后
  `/api/v1/login/phone/submit-code` 出现 `httpx.ReadTimeout`；系统又创建第二条短信订单，
  第二条未收到后覆盖了真实过程。

### 根因

验证码提交是有副作用的请求：浏览器可能已经完成输入和登录，但 Web 没有收到 MCP 的响应。
旧逻辑把响应超时直接交给外层浏览器重建策略，没有在原会话确认实际登录状态；此外只检查
异常消息文本，消息不含 `ReadTimeout` 类名时还会漏掉瞬态异常识别。

### 永久修复

- 验证码提交发生超时、连接中断等瞬态异常后，不立即关闭或重建当前浏览器。
- 在原会话按 1 秒、2 秒、4 秒退避复查登录状态；任一次确认已登录就继续创作者中心导出，
  不再发第二条验证码。
- 异常识别同时使用异常类型和消息文本，空消息的 `httpx.ReadTimeout` 也能进入恢复分支。
- 三次均确认未登录时才把原异常交回既有重试策略，非瞬态业务错误仍立即失败。

### 验证

- 新增“验证码提交超时、第二次状态检查确认已登录”的自动化回归用例。
- `backend/tests/test_xhs_flow.py` 共 110 个测试通过。
- 当前为本地修复，发布后需用历史误判账号验证日志出现
  `验证码提交响应异常但实际登录已成功`，且不得创建第二条短信订单。

## 2026-08-20 创作者登录探测重定向导致浏览器上下文销毁

### 现象

- 创作者中心互动同步在“检查登录状态”阶段返回 HTTP 500，MCP 详情包含
  `Execution context was destroyed`。
- 部分账号登录预检显示已登录，但进入数据导出页后又被 401 重定向到登录页。
- `httpx.ReadTimeout` 等异常没有消息文本时，历史记录只显示空错误或批次汇总。

### 根因

1. 创作者中心恢复 Cookie 时会连续重定向，Rod 的旧 JavaScript execution context 会失效；
   原探测逻辑继续使用旧上下文并把瞬态 CDP 错误作为最终失败。
2. 登录探测使用创作者首页通用文字作为成功标志，页面壳先出现、鉴权重定向后发生时可能误判。
3. 导出阶段发现 401 后没有账号内恢复分支，只能依赖整套浏览器会话重建。
4. Web 对空字符串 `RequestError` 直接抛出，丢失了 `ReadTimeout` 等异常类型。

### 永久修复

- 登录预检改为新建隔离标签页访问实际数据分析页，以导出入口、已登录无权限状态或连续四次
  稳定创作者页面壳作为成功依据；登录页则明确返回未登录。
- 页面重定向导致上下文失效时，先等待替换文档可用；仍不可用则关闭探测页并最多重建三次。
- 导出遇到瞬态 CDP/ReadTimeout 错误时保留登录态重试一次；遇到创作者 401 时清理旧会话、
  重新执行对应账号类型的登录策略，再导出一次。
- 所有 HTTP 请求异常写入异常类型和中文兜底信息；用户取消不作为瞬态错误重试。
- 本修复只修改 Web 和 xiaohongshu-mcp，不修改 phone-cloud、Windows Agent 或设备扫码脚本。

### 发布后验证

- 使用历史中出现过上下文销毁的账号执行同步，登录探测不得再因单次重定向直接失败。
- 已登录账号必须直接导出；401 账号必须出现“自动重新登录”阶段后再导出。
- 云手机/Poco/双开入口失败仍按原始设备错误返回，不得被改写成浏览器错误。
- 同步历史必须保存账号级最终错误，不能只显示批次失败数量。

## 2026-08-20 创作者登录二维码获取超时或页面枚举 500

### 现象

- 员工号已进入“直接扫码登录”分支，但尚未创建 `phone-cloud` 扫码任务便失败。
- 任务页的失败原因为空，后端 traceback 为 `_get_mcp_login_qrcode` 中的
  `httpx.ReadTimeout`。
- 直接调用 `phone-cloud` 扫码接口可以成功，因此不能把该故障归因于手机扫码脚本。
- 环境 29 曾在 MCP 连接浏览器后、定位页面阶段仅用 71ms 返回 HTTP 500；日志只有
  `login qrcode: locating existing xiaohongshu page`，没有进入 `page located`。

### 根因与修复

外层浏览器会话有两次重建机会，但第二次会话在生成二维码页面等待超过 45 秒后会直接
耗尽机会。`ReadTimeout` 的字符串为空，又导致任务错误摘要为空。

另一种情况是外部浏览器 CDP 连接尚在，但首次枚举页面瞬态失败。旧 MCP 直接返回 500，
Web 又只记录 HTTP 状态码且不重试，因此可恢复的浏览器连接波动被记成账号最终失败。

`_get_mcp_login_qrcode` 现改为在同一浏览器会话内最多请求三次，按 1 秒、2 秒退避；
MCP 页面枚举失败时会丢弃当前进程缓存的 CDP 连接并重连，最多三次。Web 对二维码接口
HTTP 5xx 同样最多重试三次，并保留 MCP 返回的 `details`。最终仍失败时返回包含异常类型、
HTTP 状态和原始详情的中文错误。该修复只涉及 `web` 后端和 MCP，不修改 `phone-cloud`
或 Windows Agent 的扫码步骤。

### 验证

- `backend/tests/test_xhs_flow.py` 共 109 个测试通过；MCP 所有 Go 包编译通过。
- 环境 133 的后续任务已成功越过二维码获取阶段并创建手机扫码任务。
- 环境 148、151、122、140 完成真实创作者中心导出和入库，共处理 476 行。
- 环境 29 修复后二维码接口返回 200，并识别出云登实际登录账号与配置 ID 不一致；系统自动
  清理旧会话后成功创建手机扫码任务。后续失败明确来自 Windows Agent 的 Airtest/Poco
  worker 退出，证明 Web/MCP 故障与云手机执行故障已正确分层。

## 2026-08-18 创作者中心互动同步导出超时

### 影响

- 同步任务：`7d664b9464bb469ea0cc6704b322f655`
- 请求：`95dd87554fec4936ab18e121f6641947`
- 云登环境：`81`
- 短信登录成功，但创作者中心表格未下载，任务最终失败。

### 时间线与特征日志

1. `10:38:14` 小红书自动登录完成并开始导出。
2. MCP 输出 `browser=/tmp/xhs-creator-export-* container=/tmp/xhs-creator-export-*`。
3. 网络响应捕获失败后回退到浏览器下载。
4. 等待下载文件 180 秒仍无结果。
5. `10:42:07` 导出接口耗时约 3 分 53 秒后返回 HTTP 500。

看到浏览器目录为 `/tmp/xhs-creator-export-*` 时，即可判定 Windows 下载双路径配置
没有生效，不需要继续等待完整超时。

### 根因

云登浏览器运行在 Windows 宿主机，MCP 运行在 Linux 容器。线上已经存在
`C:/projects/web/uploads:/app/uploads` 挂载，但 Compose 没有把宿主机上传根目录和
容器上传根目录传给 backend。MCP 因而回退到 Linux 临时目录，并把 `/tmp/...`
错误地下发给 Windows 浏览器。

### 永久修复

`docker-compose.yml` 的 backend 环境固定透传：

```yaml
XHS_MCP_BROWSER_DOWNLOAD_DIR: "${XHS_MCP_BROWSER_DOWNLOAD_DIR:-C:\\projects\\web\\uploads\\mcp-downloads}"
XHS_MCP_CONTAINER_DOWNLOAD_DIR: ${XHS_MCP_CONTAINER_DOWNLOAD_DIR:-/app/uploads/mcp-downloads}
```

Windows 根目录 `.env` 设置：

```dotenv
UPLOADS_HOST_PATH=C:\projects\web\uploads
```

当前 Windows 部署会解析为：

```text
XHS_MCP_BROWSER_DOWNLOAD_DIR=C:\projects\web\uploads\mcp-downloads
XHS_MCP_CONTAINER_DOWNLOAD_DIR=/app/uploads/mcp-downloads
```

如果以后把文件迁移到 D 盘，必须同步修改 `UPLOADS_HOST_PATH`、
`XHS_MCP_BROWSER_DOWNLOAD_DIR` 和 Compose 的卷挂载，不得只修改其中一处。

### 发布后验证

```powershell
docker inspect web-backend-1
docker exec web-backend-1 printenv XHS_MCP_BROWSER_DOWNLOAD_DIR
docker exec web-backend-1 printenv XHS_MCP_CONTAINER_DOWNLOAD_DIR
docker exec web-backend-1 ls -ld /app/uploads/mcp-downloads
```

验收标准：

- backend 的挂载源与 `XHS_MCP_BROWSER_DOWNLOAD_DIR` 的父目录是同一 Windows 目录。
- 容器目录 `/app/uploads/mcp-downloads` 可读取。
- 新任务日志显示浏览器目录为 Windows 路径，容器目录为 `/app/uploads/mcp-downloads`。
- 创作者中心导出成功，后端进入 Excel 解析和数据落库阶段。

### 第二层验证

首次补齐变量时使用了 `C:/projects/web/uploads/mcp-downloads`。变量虽然已生效，但
真实任务在网络响应捕获失败、回退浏览器下载后仍未落盘。独立 MCP 诊断改用原生
Windows 路径 `C:\projects\web\uploads\mcp-downloads` 后，导出接口返回 HTTP 200，
成功读取 `20,851` 字节 Excel。

因此浏览器路径必须使用 Windows 反斜杠；不能因为日志不再显示 `/tmp` 就提前判定
修复完成。最终验收必须以真实导出返回 200 并完成解析落库为准。

### 页面加载无限等待

最终正式任务还暴露出另一条独立风险：后端已经请求 MCP 导出接口，但 MCP 尚未输出
“创作中心导出下载目录”，浏览器也没有创作者中心数据页。定位到导出动作在打开
小红书首页和创作者中心数据页后直接调用无超时的 `WaitLoad()`；弱网或页面存在长期
pending 资源时会一直停在页面加载阶段，尚未执行导出按钮点击。

识别规则：

- 已出现“开始导出创作中心笔记数据”。
- 长时间没有“创作中心导出下载目录”。
- MCP 进程仍存活，登录状态正常。

修复要求：两处页面加载等待必须设置 20-30 秒上限；超时只记录警告，继续按页面元素
查找“导出数据”。该修复属于 MCP 源码变更，发布后仍需重新跑正式互动同步全链路。

### 回滚

若重建 backend 后出现异常，恢复上一版 Compose 并只重建 backend。该改动不涉及
数据库迁移，不需要回滚数据。

## 2026-08-18 已登录账号被误判后重复接码

### 影响

- 创作者中心互动同步在云登账号已有有效登录态时，仍创建短信取码订单。
- 重试任务等待不存在的验证码直至订单过期，无法进入创作者中心导出。

### 根因

MCP 的常规 `/api/v1/login/status` 为保护扫码后的二次短信验证页面，只检查当前已打开
的小红书标签页，不执行导航。云登保留了有效 Cookie，但启动时没有小红书标签页，
因此被误判为未登录。

### 永久修复

- MCP 登录状态接口新增可选参数 `probe=true`。
- `probe=true` 仅在同步开始前使用：新开临时创作者中心标签页验证持久化 Cookie，
  验证后立即关闭。
- 登录流程中的状态轮询不传该参数，继续保持不导航，避免破坏二维码或二次验证码页面。
- Web 后端仅在 `_ensure_xhs_creator_login` 的首次检查传 `probe=true`。

### 发布后验证

- 使用当天曾成功同步、确认仍有登录态的同一云登环境发起单账号互动同步。
- 日志应先出现 `GET /api/v1/login/status?probe=true`，随后直接出现
  `开始导出创作中心笔记数据`。
- 此任务期间不得出现创建短信取码订单或请求小红书发送验证码的日志。
- 导出、Excel 解析和数据落库必须完成；不能只以登录状态接口返回 200 作为验收。

## 2026-08-19 创作者中心发布时间解析为空

### 影响

- 创作者中心 Excel 导出和互动指标同步成功，但新发现帖子的 `published_at` 为空。
- 尚未由主页同步补齐的帖子无法按发布日期正确筛选和匹配。

### 根因

导出文件的“首次发布时间”真实格式是 `2026年08月18日17时01分05秒`。解析器只替换了
“年月日”，没有处理“时分秒”，因此日期转换失败；原始 Excel 有值，数据库写入链路
没有丢字段。

### 永久修复

- 日期解析同时规范化“年月日时分秒”，继续兼容已有的横线、斜线和 Excel 日期对象。
- 回填时同时计算旧版“标题 + 原始中文时间 + 出现序号”和“标题 + 空时间 + 出现序号”
  两类指纹，匹配后迁移为包含标准发布时间的新指纹，防止历史记录因指纹变化被重复创建。
- 单元测试使用创作者中心真实格式，不再只使用 `2026-08-14 10:30` 这种理想化样例。
- 发布前用真实导出文件验证总行数与发布时间解析成功行数完全一致。

### 发布后验证

- 重跑受影响账号的创作者中心互动同步，利用原始导出重新回填发布时间。
- 检查 `creator_synced_at IS NOT NULL AND published_at IS NULL` 的数量应归零；若主页或
  源数据确实缺时间，必须保留原始值并单独列明，不能静默忽略。
- 抽查北京时间原值写入数据库后应转换为 UTC naive，例如
  `2026年08月18日17时01分05秒` 对应 `2026-08-18 09:01:05`。
- 账号数据列表必须按 `published_at` 倒序展示；不能继续仅按首次抓取的 `sort_index` 排序，
  否则创作者中心新发现的最新帖子会因追加序号而落到后续分页，看起来像“没有同步”。

## 2026-08-19 创作者中心并发打开浏览器后不继续、手机号未填写

### 影响

- 三个账号并发同步时，云登浏览器都已打开，但部分任务长期停在登录检测或导出前。
- 单账号未登录时，页面已进入手机号登录弹窗，但偶发没有填写手机号。
- 取消等待验证码的任务后，任务仍可能继续轮询到接码订单过期。

### 根因

1. MCP 的 `/health` 只证明 HTTP 服务启动，没有验证 CDP 已能操作云登浏览器。
2. 登录探测、创作者中心导航和部分扫码登录路径存在无上限 `WaitLoad()`；页面有长期
   pending 请求时不会继续，也不会返回可重试错误。
3. 手机号使用普通键盘输入，没有回读页面实际值；React 受控输入框偶发未接收到更新，
   后端仍会继续点击发送。
4. 并发 MCP 共用同一下载目录并扫描“最新文件”，存在读取其他账号导出文件的风险。
5. 等待短信的轮询没有检查任务取消标记，导致取消反馈不及时。
6. 成功分支返回时只关闭了 MCP，未关闭云登浏览器；多轮同步后会残留浏览器并持续占用资源。

### 永久修复

- MCP 启动后除 `/health` 外，再调用一次不导航的登录状态接口，真实验证 CDP 连接。
- 每个账号最多执行两次独立浏览器会话；浏览器/CDP/页面超时会关闭旧会话并重建，
  已发送验证码后的接码错误不自动重试，避免重复发码。
- 所有本链路页面导航使用 25-35 秒有界等待；导出总流程使用 4 分钟上限并输出五阶段日志。
- 手机号通过原生 `HTMLInputElement.value` setter 写入，触发 `input/change/blur`，回读值
  完全一致后才允许点击“获取验证码”；验证码输入复用同一校验逻辑。
- 每个 MCP 会话使用独立的 Windows 浏览器写入目录和容器读取目录，任务结束后清理。
- 浏览器释放移入会话级 `finally`，成功、失败和重试都会关闭对应云登浏览器。
- 等待验证码时每轮检查任务取消状态；页面进度明确区分登录检测、填写手机号、等待短信、
  提交验证码和导出表格，不再统一显示为“正在读取”。

### 本地真实验证

- 单账号已登录：`本海` 完成 755 行导出、解析和落库，总耗时约 58 秒。
- 三账号并发：`本海 / 优车运营官 / 爱车小P` 全部完成，共导出 1,086 行；其中一个
  登录探测真实返回 HTTP 500，自动重建浏览器后成功，验证了故障恢复分支。
- 单账号未登录：`跳想超执1` 页面手机号写入后回读校验成功，并检测到发送倒计时；
  后续因绑定手机未回传短信而停止测试，没有重复触发验证码。

### 发布后验证

- 先确认线上没有正在执行的创作者中心同步任务，再只重建 backend，避免扩大影响面。
- 用三个已登录账号并发同步，必须全部经过 CDP 深度探测并完成导出、解析、落库。
- 日志中的每个 MCP 必须有不同的 `session-*` 下载目录。
- 未登录账号只在业务允许时测试一次；必须先看到“手机号已写入并校验”，再看到倒计时。
- 验收以同步历史中的成功/失败明细和数据库行数为准，不能只看浏览器是否打开。

## 2026-08-19 创作者中心无权限页误报导出 500、同名环境记录串行

### 影响

- 创作者中心实际显示“暂未开通数据权限”或已跳转登录页时，MCP 仍继续寻找“导出数据”，
  最终统一报 HTTP 500，历史记录无法看出真实原因。
- 批次开始后环境被删除或停用时，被当成同步失败。
- 同一批次中存在同名环境时，进度仅按账号名匹配，后一个环境的结果可能写到前一个环境，
  未命中的记录最终被批次总错误覆盖。

### 根因

1. 登录预检曾把普通小红书网页的登录态当成创作者中心登录态，两个域的会话并不等价。
2. 导出前没有识别创作者中心登录页和“暂未开通数据权限”页面。
3. Web 后端收到 MCP 非 200 响应时丢弃了 `details`，只保留 HTTP 状态码。
4. 同步历史以 `account_name` 作为进度关联键，而环境整理期间账号名可能重复或变更。

### 永久修复

- 首次登录预检始终使用独立标签页验证创作者中心域，不再接受普通小红书标签页作为依据。
- 导出前明确等待并识别三种状态：可导出、创作者中心登录失效、未开通数据权限；页面空白
  10 秒自动刷新一次，仍异常时返回 URL 和页面摘要。
- 后端保留 MCP 的错误码和 `details`；短暂登录状态 HTTP 500 在同一浏览器会话内重试三次。
- “未开通数据权限”作为可解释的跳过结果，不再重建浏览器两次或计入系统异常。
- 所有账号进度携带 `environment_id`，历史记录和影子任务优先按环境 ID 关联，账号名仅作旧数据兼容。
- 批次执行期间已删除或停用的环境自动跳过；没有完成回执的记录单独标记重试，不再套用批次总错误。
- 手机云控新版设备数据使用 `xhsId` 返回小红书 ID；Web 同时兼容 `xhsId` 和历史字段，
  账号名称增加负责人后缀或改名时仍优先按稳定 ID 定位 app1/app2，不再误报未配置槽位。

### 发布后验证

- 对已退出错误账号的环境发起同步，必须先走对应环境手机号的验证码登录，再进入创作者中心。
- 对真正未开通数据权限的账号，应记录“已跳过”及原始原因，不出现导出 HTTP 500。
- 对一个正常已登录账号执行完整导出，必须继续完成 Excel 下载、解析和入库。
- 验证同步历史中的每条记录都带正确环境 ID；环境在任务期间被移除时不计入失败数量。

## 2026-08-19 扫码后二次验证码提交到旧登录页

### 影响

- 二维码扫描和手机云控任务已经成功，第二条验证码也已由短信中台收到，但最终仍提示
  “二次验证码已提交，但小红书登录态确认失败”。
- MCP 接口返回提交成功，实际验证码却被填入仍保留在浏览器中的首轮手机号登录页。

### 根因

- 首轮登录页和扫码后的二次验证页会同时存在；旧选页逻辑优先选择带“重新发送”倒计时的页面。
- 二次验证页使用精确文字“验证”的按钮，通常没有首轮手机号输入框和发送倒计时，但旧接口无法区分
  首轮提交与扫码后提交。

### 永久修复

- 验证码提交接口增加可选 `post_qr` 模式；首轮验证码保持原有倒计时页选择逻辑。
- 扫码后的第二条验证码只选择同时存在验证码输入框和精确“验证”按钮的页面，不填写手机号，
  也不再回退点击普通“登录”按钮。
- 找不到二次验证页或“验证”按钮时返回明确错误，禁止产生“接口成功但页面没提交”的假成功。

### 发布后验证

- 使用一个已退出登录、设备在线且允许进入创作者中心的账号完整执行一次：首条短信、扫码、
  第二条短信、登录态确认、导出、解析和入库。
- 日志必须出现“已定位带精确‘验证’按钮的验证页”，随后登录状态变为已登录；不得再次出现
  第二条验证码已收到但连续 30 秒登录状态仍为假的情况。

## 2026-08-19 企业员工号不能先走手机号验证码

### 影响

- 系统此前无法区分企业专业号和企业员工号，所有未登录账号都会先尝试手机号验证码。
- 企业员工号的小红书登录策略要求先扫码，首轮验证码登录不会成功，还会浪费一次接码等待时间。

### 永久修复

- `xhs_environments` 增加账号类型配置，支持企业专业号、企业员工号和个人号，历史账号默认企业专业号。
- 企业员工号未登录时直接生成二维码并下发到其小红书 ID 对应的手机 App；二维码前预挂二次接码订单，
  扫码后若自动触发验证码，可以立即接收并提交。
- 企业专业号继续使用“首条验证码 -> 按需扫码 -> 按需二次验证码”，不改变原有成功链路。
- 账号类型仅按台账中的小红书 ID 精确回填，不按可能重复或变更的昵称猜测。

### 发布后验证

- 各选一个企业专业号和企业员工号退出登录后执行创作者中心同步。
- 企业员工号日志中不得出现“第一条接码订单已创建”或“第一条验证码已触发发送”，必须直接出现
  “企业员工号使用扫码优先登录”。
- 企业专业号必须仍先填写手机号并检测发送倒计时；两种账号最终都要完成导出、解析和入库。
# 2026-08-20 创作者中心登录错号被误判为无数据权限

- 现象：云登环境中残留其他小红书账号时，登录状态接口只返回“已登录”，创作者中心导出随后返回“暂未开通数据权限”，旧逻辑会把该环境记为成功跳过。
- 根因：登录预检只判断会话是否有效，没有把当前主页 `redId` 与环境配置的“小红书 ID”进行核对。
- 修复：收到无数据权限后调用 MCP `/api/v1/user/me` 读取当前账号 ID；ID 不匹配时清理该云登环境的浏览器 Cookie，按企业员工号/企业专业号策略重新登录，再次校验 ID 后重试导出。
- 边界：ID 一致但仍返回无权限时才按真实无数据权限跳过；读取不到身份时不自动清会话，避免误登出正确账号。
- 验证：`backend/tests/test_xhs_flow.py` 100 项通过；MCP `go test ./... -run '^$'` 全包编译通过。

## 2026-08-20 浏览器已登录但同步仍等待验证码

### 影响

- 小红书首页登录预检短暂返回未登录后，系统创建验证码订单并进入最长 180 秒的短信等待。
- 云登浏览器随后已经恢复为登录状态，后端仍只轮询短信订单，不再复查浏览器，导致并发槽位长期被占用。

### 根因与修复

- 登录预检改为只打开 `https://www.xiaohongshu.com/explore` 检查小红书主站登录态；确认登录后才进入创作者中心。
- 原短信等待循环只检查验证码中台，没有把“浏览器已自行恢复登录”作为另一种成功条件。
- 请求验证码接口若在打开首页时发现已登录，Web 后端立即采用该结果，不再忽略并继续等待短信。
- 首轮验证码等待现在会同步复查当前 MCP 浏览器登录态；检测到已登录后立即取消未完成的验证码订单，结束登录流程并进入创作者中心导出。
- 登录态复查异常不会中断短信监听，正常验证码、双卡兜底和扫码后二次验证码流程保持原逻辑。

### 发布后验证

- 已登录账号即使预检短暂误判，也应在下一次短信轮询周期内显示“已确认登录，正在进入创作者中心”。
- 后端日志必须出现“等待验证码期间检测到浏览器已登录”，随后进入导出阶段，不能继续等待到 180 秒补发。

## 2026-08-20 登录探测反复打开小红书首页

### 现象与根因

- 弱网下首页 15 秒内没有同时满足旧的登录/未登录元素规则，MCP 会重建探测页 3 次，Web 后端收到 500 后又重试 3 次。
- 未登录判定只识别登录框/手机号输入框，页面只显示“登录”按钮时无法稳定结束。
- 拿到物理手机接码锁后递归进入登录流程，又执行了一次会导航的首页探测。
- 隐藏在 DOM 中的登录框也被当成可见登录框，存在已登录误判风险。

### 永久修复

- 首页登录探测观察窗口由 15 秒提高到 40 秒，明确识别状态后仍立即返回。
- 每个登录阶段只允许一次导航探测；探测页在后台标签打开，不抢占用户浏览器焦点。
- 探测导航上下文短暂失效时，改为复用已有小红书页面做无跳转检查，不再循环新建首页。
- 未登录识别同时支持可见“登录/立即登录”按钮；登录框和手机号输入框只在实际可见时生效。
- 获得手机接码锁后只做无导航登录复查，不再第二次打开首页。
