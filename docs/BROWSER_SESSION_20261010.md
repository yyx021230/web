## 兼容与边界

| 链路 | 处理 |
|---|---|
| 浏览器 | 显式开关启用会话；30分钟访问Token，HttpOnly刷新Cookie；同源会话代理 |
| 脚本/外部API | 原`/auth/login`响应和有效期不变，不套用浏览器闲置规则 |
| Worker/云手机/小红书/模型密钥 | 不改各自认证；浏览器退出不取消已受理任务 |
| 旧浏览器Token | 开关关闭时兼容；启用后旧Token在原有效期内过渡，新登录进入会话；旧Token不能伪称支持服务端即时撤销 |
| 发布/上传/审核 | 凭证先续期；只允许明确认证拒绝的安全读请求恢复，写请求不自动重放 |
| 权限 | 沿用数据库实时用户/角色判断，未扩大业务访问范围 |

公网HTTP不启用长期刷新Cookie；开启前必须配置HTTPS及精确允许Origin。默认关闭开关，不让未迁移数据库或旧部署被自动切换。新增表为additive迁移；回滚优先关闭开关并回滚应用，保留表，不删除业务或会话记录。旧应用不理解新会话JWT的撤销/闲置限制，回滚会放宽新访问Token剩余寿命内的校验，不能称为安全语义完全等价。

### 已知边界与回滚

- 活跃时间每分钟最多写一次，闲置边界是分钟级精度；页面可见访问/可信前台输入等算使用。自动轮询与续期不算使用，离线活动无法延长服务端时间。
- Web Locks协调同浏览器标签页的登录/刷新/退出；无Web Locks的浏览器仅有服务端CAS和共享随机nonce保护，未承诺其全部跨标签Cookie到达顺序。正式启用前明确支持的浏览器版本并验收。
- 丢响应恢复窗口为服务端30秒、前端nonce缓存25秒；不是无限容错。旧已签名刷新凭证超窗重用会撤销会话，需要重新登录。
- 同账号弹窗重登保留主工作区已挂载草稿，不等于刷新页面后所有未保存表单均持久化；后台管理守卫和业务权限仍以服务端为准。
- 仅新增会话表及撤销API，未新增“设备管理/全部退出”专门界面、审计报表或会话历史清理定时任务；长期保留/清理策略应在正式启用前按审计需求确定。
- 旧API/旧浏览器JWT仍有24小时有效期，不具备session级撤销；不能把新会话规则宣传成所有凭证立即统一生效。
- 回滚首选关开关并回滚兼容应用，保留新增表；关闭开关并不会让已有新会话继续刷新，用户需要重新登录。旧应用不识别 `sid`，新访问Token剩余不超过30分钟期间会放宽撤销/闲置校验，应纳入回滚风险。未在业务库执行downgrade。
- 尚未完成生产HTTPS、Windows真实core/Hermes共库核对与启用验收；本轮通过不等于已经部署或保证绝无缺陷。
