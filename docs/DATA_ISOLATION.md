# 数据隔离与共享设计规范 (Data Isolation & Sharing)

本文档定义了 AI Creative Studio 中的数据访问控制、用户隔离及管理员权限规范。

## 1. 用户维度 (User Level) - 数据隔离

每个普通用户的数据在默认情况下是**完全隔离**的。

- **素材 (Materials)**: 用户的素材库是私有的。用户只能看到自己上传或生成的素材。数据库通过 `Material.created_by` 进行约束。
- **AI 任务 (AI Tasks)**: 用户只能查看自己的生图历史和任务进度。数据库通过 `AITask.user_id` 进行约束。
- **工作流任务 (Workflow Tasks)**: 用户只能看到自己运行的工作流任务及其结果。数据库通过 `DifyTask.user_id` 进行约束。
- **文案 (Copywritings)**: 用户的文案库是私有的。数据库通过 `Copywriting.user_id` 进行约束。

## 2. 工作流共享与权限 (Workflow Permissions)

工作流遵循 **"管理员配置，用户使用"** 的原则。

- **全局可见性**: 管理员在后台配置 Dify 工作流。
- **RBAC 授权**: 管理员可以为特定用户分配特定工作流的访问权限。
- **默认规则**: 未被授权的工作流对普通用户不可见且不可调用。

## 3. 管理员维度 (Admin Level) - 全局全视

管理员拥有全局数据访问权限，用于监控、审计和资源管理。

- **全站监控**: 管理员可以查看全站所有用户的活跃任务、生图历史和工作流执行情况。
- **资源管理**: 
    - **素材管理**: 管理员可以查看并删除全站任何用户的素材（用于清理违规内容或释放空间）。
- **数据统计**: 管理员可访问全局仪表盘，包括：
    - 全站存储空间占用排行。
    - 热门工作流运行排行。
    - 模型使用频率分布。
    - 用户活跃度统计。

## 4. 共享资源 (Shared Resources)

目前系统中存在的共享资源包括：

- **车型库 (Car Models)**: 基础参考数据，全站用户共享。

独立模板库和编辑器已下线，历史项目与模板表仅保留数据兼容，不再提供读写接口。图库中的 AI 模版仍按素材权限管理，不等于已下线的公共模板库。

## 5. 技术实现方案

- **后端 (FastAPI)**: 
    - 普通接口：通过 `current_user` 自动注入 `user_id` 过滤查询。
    - 管理接口：位于 `/api/v1/admin/` 路径下，通过 `require_admin` 装饰器校验权限，支持可选的 `username` 参数进行交叉筛选。
- **前端 (Next.js)**: 
    - 根据用户角色（`admin` vs `user`）动态渲染侧边栏导航和功能模块。
    - 管理员后台独立于用户操作界面，提供全站视角。

## 6. 浏览器会话边界（本地候选）

- 新会话开启后，访问 Token 的 `sid` 必须与当前用户、有效会话匹配；权限仍实时读取数据库角色与业务归属，不以浏览器缓存授予权限。
- 刷新 Cookie 仅发送到前端同源 `/api/auth-session` 路径，不暴露给页面脚本；会话表不存明文刷新凭证。刷新、退出等 Cookie 操作同时检查精确 Origin 和专用请求头。
- 同用户重新登录不重放业务写请求；换账号则重新加载页面，避免保留上一用户挂载的草稿/任务视图。退出不取消服务端已受理任务。
- 旧脚本/API JWT 与浏览器会话分开，兼容令牌仍有原有效期，不能宣称可被新会话撤销接口立即撤销。用户禁用仍由所有受保护接口的当前用户检查阻断。
- 开关默认关闭；本轮仅使用隔离 SQLite/PostgreSQL 和假账号验证，不修改生产或现有本地业务库。启用与回滚限制见 [会话任务卡](BROWSER_SESSION_20261010.md)。
