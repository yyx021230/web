# Hermes 小红书 8×5 日产系统

这套运行器每天一次生成 8 个账号、每个账号 5 篇，共 40 篇图文。它不会自动发布。

## 固定原则

- 从完整线上文案库读取母文，代码随机、批内母文 ID 不重复。
- 文案随机候选优先避开账号历史/批内高度雷同结构；低于高相似边界后仍随机选，不一味选差异最大的母文。主选和备用保留结构去重，防止“ID 不同但模板相同”。图片母版保留原择优策略。
- 随机窗口内若全是高度近似版式，只扩大一次候选池；近似度阈值是软约束，确实无解时继续选最不相似项并在检查点标记，不进入死循环。
- 账号历史只用于避重和效果观察，不用于生造账号人设。只有系统产出与已发布
  帖子能准确匹配、并积累发布 48 小时后的样本后，才启用轻量效果加权。
- 选定账号后按 `environment_id` 并发查询各账号最近15条已同步有效帖子，不再限制最近14天。Hermes读完整标题与正文，不只读开头；少于15条就用已有条目，缺正文明确标记，不用更老的完整正文冒充这15条，也不主动触发账号采集。
- 只对高度相似避让：主体全文结构做车型/数字归一，忽略话题及短CTA，4-gram Jaccard 0.85是代码筛选边界，不是自然语言“85%相似”的保证。普通相似、同车型同政策可接受；同账号窗口若无可选母文，最多扩池一次，再降级择优并留记录，不无限循环。
- 生成后记录与最近15条最接近的帖子ID及分数；高度相似仅给审核提醒，不把相似度升级成新的硬错误。此项是文本结构避重，不冒充图片视觉相似检测。新任务冻结 `account_history.snapshot.json`，旧任务断点续跑保留原快照，不重写历史结果。
- Hermes 每篇只复刻一篇指定母文，保留结构、Emoji、留资位置和末尾话题。
- 母文与母图从各自素材池独立随机，不做“报价图必须配报价文案”的硬绑定。只写“报价已更新”的普通留资句不算报价文案；若随机抽到多配置报价母图，可用当前政策表的完整配置价格行作为正文之外的互补信息，但不得为了配图反向硬改正文。
- 当前资料不支持母文参数时，只能换同一语义类别的已知信息；否则改为对应实车观察问题或删除无依据条目/整段，并轻改相应小标题。不能用补贴、质保填产品体验槽，也不能连续用“以官方发布为准/待公布”等占位语硬撑结构。
- 明确禁用词由代码替换；“免费”仅去掉修饰词，不改成“不设门槛”，不扩大权益适用对象。只有事实、车型、金额、日期、配置、禁用词等硬错误阻断。
- 图片轻改线上提示词母版，并只传对应车型库图片作为车辆辅助图。
- 图片母版按真实可见文字槽逐槽复刻：保留通用文案、句式、顺序、层级和CTA位置，只替换汽车关键事实；普通海报允许2–9槽，多配置报价母版允许2–30槽，禁止把报价表压成几句普通权益文案。
- 多配置报价图只允许单一车型的多个配置，配置名和金额必须逐项来自当期结构化政策；多车型报价单仍不进入生图池。多配置不等于表格：母版是便利贴/卡片时保留原载体，母版是表格才保留表格。按原版容量选择已登记配置和价格，不为了塞入全部政策数据而增加载体或改版式。
- 图片方案必须逐槽记录“母图原文字 → 保留/最小替换 → 成图文字”，多个槽无法在母版提示词中定位时直接换母版，不允许凭空重写结构。
- 主、备用图片母版都失败时，再自动换最多 2 套批内未使用且结构不重复的安全母版，不盲目重复同一错误。
- 生图最多 5 路并发；连接中断后继续查询原 task_id，不重复提交。
- 成图使用本机 Apple Vision OCR 回查金额、日期、配置、品牌、车型和禁用词。
- 报价图不仅拦截额外错误金额/配置，也要求计划中的每个金额和配置名都能被OCR回读；漏字、错字或被生图模型省略同样视为硬错误。
- OCR 对小字中的金额、日期、配置、品牌和车型降低置信度门槛继续硬审，避免页脚报价因字号小被跳过。
- 40/40 通过才写入 `delivery.json`，否则只生成 `delivery_candidate.json`。
- 同一日期使用进程锁；重复启动第二个批次会立即退出，不会重复向生图后台提交任务。

## 配置

复制 `.env.example` 为 `.env`，填写：

- `INTERNAL_RELAY_API_KEY`
- `XHS_BACKEND_PASSWORD`，或直接填写 `XHS_BACKEND_TOKEN`

账号和并发参数在 `config/daily_8x5.json`。车型与政策不再人工写死：政策源配置在
`config/policy_source.json`，操作侧补充规则在 `config/policy_overrides.json`，
每次运行前自动把最新政策报告解析成 `config/cases.json`。

当前政策源是 WorkBuddy 的《零跑全系购车政策分析报告》。即使共享文件名仍保留
旧月份，也以当天生产批次所在月份作为运营确认期；公开内容只使用“本月、近期、
当月底前”这类当前口径。报告中的具体到日活动会被排除，不会把过期的某日锁单礼
改写成新日期。跨月时，如果政策表内容指纹没有变化，系统拒绝生产，防止把上月
政策直接沿用到下月。

政策表满足以下条件时自动开放多配置报价母版：至少两行配置，且每行都有配置名、
官方指导价、报废更新后测算价和置换更新后测算价。补贴后金额必须带适用条件/测算
语义，不能写成无条件成交价或落地价。

网络临时失败时可以使用本月最近一次验证通过的本地政策快照；解析结构变化、车型
缺失或跨月仍未更新时直接停止，不让不完整政策进入文案和图片。

正式运行前先做只读自检。它检查政策有效期、Hermes Python 3.11、插件、OCR、
磁盘空间、内部中转、线上文案/提示词/车型图片库；不会调用模型，也不会提交生图任务：

```bash
./ops/xhs_hermes/run_daily_8x5.sh --self-check
```

只同步并检查政策表，不调用模型、不提交生图：

```bash
./ops/xhs_hermes/run_daily_8x5.sh --sync-policy-only
```

## 使用

只规划40篇母文和图片母版，不调用模型或生图：

```bash
./ops/xhs_hermes/run_daily_8x5.sh --plan-only
```

只完成40篇文案：

```bash
./ops/xhs_hermes/run_daily_8x5.sh --copy-only
```

完整生成40篇图文：

```bash
./ops/xhs_hermes/run_daily_8x5.sh
```

只生成某一个已配置账号的5篇图文：

```bash
./ops/xhs_hermes/run_daily_8x5.sh --account-id 6
```

单账号输出位于 `outputs/xhs_hermes/YYYY-MM-DD/account-<账号ID>/`，不会覆盖同日
完整40篇批次。

某张图连续两次被上游拒绝时，可保留已经审核通过的文案，封存失败记录并强制
换一套未使用的图片母版，只补指定帖子：

```bash
./ops/xhs_hermes/run_daily_8x5.sh --account-id 6 --retry-image-keys 6-05
```

默认输出到 `outputs/xhs_hermes/YYYY-MM-DD/`。重复执行同一天命令会读取
`checkpoint.json` 断点续跑，不会重新生成已经完成的帖子。

Hermes 文案 worker 固定使用 `HERMES_PYTHON` 指向的 3.11 环境，不跟随系统自带
Python。每天正式运行前要求输出盘至少保留 5GB，可在配置中调整
`minimum_free_gb`。

## 每日状态

每篇依次经历：

`planned → copy_ready → image_plan_ready → image_submitted → ready`

检查点在每次状态变化后原子写入。图片任务提交后立即保存 task_id；遇到临时
502/503/504 只继续轮询，遇到并发容量提示则等待空位。

## 交付内容

- `delivery.json`：完整机器可读结果和来源账本。
- `图文交付.html`：按账号分组的图文配对、母文对照、母图对照、逐槽文字映射、改造前后提示词。
- `images/<账号ID>/`：本地成图。
- `checkpoint.json`：可恢复运行状态。

检查点中的 `account_memory` 会列出每个账号的近期内容量、正文缺失量、近似
重复量、成熟帖子中位浏览和来源匹配量。系统不会因为单篇偶然高曝光就复制其
结构；没有可靠来源归因前只观察，不参与创作决策。

每次规划还会在母文和图片母版上保存 `structure_id`、账号历史相似度、批内
相似度和 `selection_relaxed`。因此既能保留真正随机抽取，也能定位某次是否因
素材库限制放宽过结构去重，不再只靠标题或素材 ID 判断同质化。

## 接入 Web 工作流

Web 后台现在只负责任务、权限、审核和发布清单，不在 API 请求里直接运行耗时的
Hermes 批次。Mac Worker 默认继续使用 Apple Vision；Windows 服务器使用 Linux
Docker Worker + 本地 CPU OCR，无需 Mac 在线。容器部署步骤和验收限制见
[Windows Docker 部署说明](docker/README.md)。

本地 Mac 启动方式：

```bash
export HERMES_WEB_BASE_URL=http://127.0.0.1:8000
export XHS_WORKER_INTERNAL_TOKEN=<与 Web 后端一致的内部令牌>
./ops/xhs_hermes/web_worker.py
```

Worker 会持续心跳、认领最早的排队任务、按任务参数生成 1—40 篇图文，并把
`delivery.json` 连同母文、母图、提示词和 OCR 审计信息回传。网络中断不会让 Web
请求一直占用；Worker 恢复后可以继续轮询任务。

- 普通用户在 `/workflows` 给自己负责的账号下发 1—5 篇单次任务，并审核该账号内容。
- 管理员在 `/admin/workflows` 配置唯一的每日 8 账号 × 5 篇任务、查看全量审核状态。
- 定时批次会按账号当前负责人分发，每位负责人只看到属于自己的帖子。
- “一键发布”目前只生成结构化发布清单并标记为待接入，不会调用任何外部发布接口。

启用定时任务前必须先完成数据库迁移、给 8 个账号分配负责人，并确认管理页上的
Worker 状态为在线。自动发布仍保持关闭，等发布接口接入后再实现发布适配器。
